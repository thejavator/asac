ASAC × the 6 pillars

Harness engineering describes what to build around a model to get a reliable agent: Instructions, Knowledge, Skills, Tools, Orchestration, Control. This page shows where each pillar lives in ASAC and what v0.4 adds to close the gaps.

Agent = Model + Harness
6 pillars → primitives
Vocabulary

Two meanings of the word "harness"

The word refers to two things at different levels. Mixing them up makes discussions confusing.

TermMeaningIn ASAC
Harness engineeringDiscipline: designing everything around the model (instructions, knowledge, skills, tools, orchestration, control)The whole asac.yaml manifest + policies
Harness (runtime)Product that runs the agentic loop: for example Claude Code, Copilot, Cursor, or Bobharness resource (v0.3), interface asac/harness-interface@2.0
Reading rule: "harness" in the broad sense = the 6 pillars; "harness" in the YAML = the runtime. Skills are part of the harness in the broad sense (pillar 3) but not part of the runtime: they are mounted by an adapter.

Agent card

An agent described by its 6 pillars

The following card could be generated by a portal for each agent: it serves as a readable "charter" for the security officer, the manager and the product owner.

dev agent — 6-pillar viewyaml
agent: dev
  # Model + runtime
  provider: var.dev_model
  harness:  var.dev_harness

  # 1. Instructions
  instructions: [security.md, java-conventions.md]
  # 2. Knowledge
  knowledge:    [project-okf]
  # 3. Skills
  skills:       [java/implementation@3.0.0]
  # 4. Tools
  tools:        [gitlab, sonar]
  # 5. Orchestration
  handlesCapabilities: [implementation]
  # 6. Control
  autonomy: review
  hooks:    [secret-scan, deps-verify]

What the card answers

QuestionPillar
Which rules does it follow?1

Note: the syntax shown here is a presentation proposal. In v0.4, instructions, knowledge, budgets and hooks are declared at the root of the manifest, as described in the v0.4 spec (frozen).

Limits

What this page does not claim

• The primitives and fields of spec v0.4 are frozen in the spec; the reference CLI, portal and runner exist; the registry does not yet.

• The six pillars are a common way to describe harness engineering; this page is an original mapping to ASAC.

• The matrix cells illustrate a typical case, not a requirement.
