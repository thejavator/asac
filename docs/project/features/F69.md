# F69. Vérification du parcours délégué

**Statut : Vérifiée.** Spec : `asac-specs-v1.md`, § 6, lot C.

## Critères

| # | Critère | Preuve |
|---|---|---|
| 1 | Un agent factice hostile lancé par le vrai runner tente quatre actions : modifier un hook, modifier `asac.yaml`, lire `~/.ssh`, appeler un hôte externe. Chaque tentative échoue, et le disque de l'hôte le confirme | `tests/test_delegate_hostile.py` : `test_modifying_a_hook_from_the_container_is_refused`, `test_modifying_the_manifest_from_the_container_is_refused`, `test_reading_a_secret_of_the_host_from_the_container_is_impossible`, `test_calling_an_outside_host_from_the_container_fails`. Vrai Docker, vraie image |
| 2 | Le contrôle d'intégrité et les hooks jugent le travail du worktree, y compris quand l'agent a écrit dans sa propre copie de `asac.yaml` | `test_the_rules_are_judged_on_the_main_checkout_whatever_the_agent_wrote` : l'agent réécrit `.asac/hooks/step-scope.sh` en `exit 0` et `asac.yaml` dans son worktree ; le vrai hook du dépôt principal tourne et refuse (`SPEC.md` absent) ; `test_modifying_the_manifest_…` : `integrity.verified`, jamais `integrity.violated` |
| 3 | Un test avec le vrai `claude` dans le conteneur produit une spécification dans le worktree et un coût réel dans l'audit ; `ASAC_REAL_CLAUDE=1` | `tests/test_delegate_real.py` (exécuté : vrai `claude` 2.1.331, `GREETING.txt` correct, `cost_usd=0.3534`, jeton absent de l'audit et des livrables). Le fichier produit n'est pas une spécification mais un fichier jugé par un hook : même mécanisme que `test_real_claude.py` |
| 4 | Les deux fichiers de test s'ignorent proprement quand Docker ou l'image est absent | `pytestmark` des deux fichiers ; vérifié : sans l'image, `1 skipped` |

## Les tests échouent-ils quand la porte est ouverte ?

Une attaque qui « échoue » parce que rien n'a tourné ne prouve rien. Chaque test vérifie d'abord que
l'agent s'est exécuté (`TOOL-RAN.txt`), puis j'ai **rouvert chaque porte** dans le code pour voir le
test échouer :

| Porte rouverte | Test qui échoue |
|---|---|
| dépôt principal monté en écriture | hook et manifeste |
| dossier personnel de l'hôte monté | lecture de la clé |
| réseau ouvert (`bridge`) | appel d'un hôte externe |
| git d'ASAC qui fait confiance au `.git` du worktree | évasion par `.git` |

La dernière n'était pas détectée au premier essai : l'attaque s'arrêtait au contrôle `step-scope`
avant le commit d'ASAC, donc le code testé n'était jamais atteint. L'attaque écrit maintenant une
`SPEC.md` valide, et le test vérifie qu'ASAC a bien commité (`step.committed`) avant de conclure.

## Limite

Sous Docker, un refus réseau n'est pas audité (contrairement à `sandbox.denied` sous `srt`) : le
test constate l'échec de l'appel sur le disque, pas une ligne d'audit. C'est la limite déclarée par
la spec (F60, § 16).
