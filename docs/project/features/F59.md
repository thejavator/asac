## Changements

- `DockerRunner` : un seul montage, `<worktree du run> -> /work`, en écriture. L'ancien montage du
  projet (`/project`, lecture seule) disparaît. `/tmp` est un tmpfs de 64 Mo.
- Le worktree vient d'un résolveur par run (`worktree_for`), branché par `make_context` sur le
  chemin que l'audit a enregistré. Un run sans worktree lève une erreur au lieu de recevoir le
  dépôt principal.

## Vérification

8 mutations du runner, toutes détectées : worktree en lecture seule, repli sur le dépôt principal,
dépôt principal monté en plus, capacités conservées, réseau forcé à `none`, clé passée par valeur,
racine en écriture, image par défaut remplacée.

## Défaut trouvé et corrigé : le commit d'ASAC faisait confiance au `.git` du worktree

Écrire dans le worktree donne aussi accès à son fichier `.git`, qui dit où est le dépôt. Un agent
peut le réécrire pour pointer sur un dépôt qu'il a fabriqué, dont la configuration nomme une
commande (`core.fsmonitor`, `core.hooksPath`, `core.pager`, `core.sshCommand`). Le commit de
l'étape, fait par ASAC **sur l'hôte**, lançait alors cette commande, avec les droits de l'utilisateur,
hors du bac à sable.

Reproduit sur le vrai code, avec un agent sous `srt` qui réécrit `.git` : le fichier témoin était créé
sur l'hôte. Corrigé : ASAC lit le vrai dossier git depuis le dépôt principal (`real_gitdir`) et lance
git avec `--git-dir`, `--work-tree` et les réglages exécutables désactivés (`git_in_worktree`).
L'affichage des fichiers du commit dans le portail suit la même règle.

- `test_a_rewritten_dot_git_cannot_make_asac_run_the_agents_command` (4 réglages) : échoue sur
  l'ancien code, passe sur le nouveau.
- `test_the_git_directory_comes_from_the_main_repository`,
  `test_a_folder_that_is_not_a_worktree_of_the_project_is_refused`,
  `test_the_files_shown_come_from_the_real_commit_not_from_a_repository_the_agent_made`.

Ce défaut existait avant ce lot : il touche le parcours `autorun` sous `srt` comme le parcours
délégué. Ce n'est plus le cas.
