# F67. Notifications vérifiées par envoi réel

**Statut : Vérifiée.** Spec : `asac-specs-v1.md`, § 6, lot B.

Chaque cible reçoit un vrai message, lu par un processus distinct du test.

## Critères

| # | Critère | Preuve |
|---|---|---|
| 1 | Récepteurs HTTP et SMTP en processus séparés, ports libres, un fichier de réception | fixture `receiver` (`tests/test_notify_live.py`) : deux `subprocess.Popen` |
| 2 | `webhook+` : `kind: gate.opened`, run, gate, rôle ; `X-ASAC-Signature` = `sha256=` + HMAC du corps | `test_webhook_receives_a_signed_gate_notification` |
| 3 | `slack+` : corps JSON avec la clé `text` et le titre | `test_slack_and_teams_receive_their_own_body_shape` |
| 4 | `teams+` : `AdaptiveCard` avec le titre | idem |
| 5 | `smtp://` : `From`, `To`, `Subject` ; STARTTLS couvert par un test unitaire | `test_smtp_target_delivers_a_mail` ; `test_smtp_target_upgrades_the_connection_with_starttls` (`tests/test_notifications.py`) |
| 6 | Cible injoignable avant une cible joignable : le run atteint sa gate, l'autre reçoit, `notify.failed` | `test_an_unreachable_target_never_stops_the_run` |
| 7 | Le message d'erreur nomme le type d'échec et omet l'URL | même test (audit du run réel) ; `test_a_failed_delivery_names_the_failure_and_hides_the_target` |
| 8 | Marqueurs `integration` et `enable_socket`, `ASAC_NOTIFY_LIVE=1` | `pytestmark` du fichier |
| 9 | `ASAC_WEBHOOK_SECRET` et `notify_targets` au § 11 de la spec | déjà présents dans la spec |

## Changements

- `tests/test_notify_live.py` : le récepteur importait `asyncore` et `smtpd`, retirés de Python
  3.12. Le processus HTTP plantait au démarrage et les 4 tests échouaient dans la fixture. Les deux
  imports sont retirés ; le récepteur SMTP utilise déjà `socketserver`.
- Le test d'injoignable vérifie maintenant le contenu du message d'erreur (critère 7), que le
  fichier d'origine ne contrôlait pas.
- 2 tests unitaires ajoutés (STARTTLS avant `login`, message d'erreur sans URL).

## Vérification

- 4 tests passent, avec 3 processus réels (HTTP, SMTP, le run). Durée : environ une minute.
- 6 mutations de `notify.py`, toutes détectées : signature sur un autre corps, en-tête renommé,
  Slack sans la clé `text`, carte Teams d'un autre type, SMTP sans STARTTLS, erreur qui expose le
  détail brut.

## Écart

Le chemin STARTTLS n'est pas joué sur un vrai serveur : le récepteur SMTP local n'offre pas TLS.
Le test unitaire couvre l'ordre (TLS avant `login`) ; la négociation reste celle de `smtplib`.
